Spec to Ship

A visual map of the development loop: make the idea legible, turn it into tests, implement against those tests, let the human verify the app, review the code, simplify the result, then ship.

Primary skills: /html-spec · /build-tests · /simplify
Human checks: spec review · test QA · app QA
Goal checks: verify red · implement to green

Skills

Press a skill to see what it contains. The workflow below uses these as the three named moves: create the spec, build the tests, then simplify after the implementation is working.

    Build the red test contract

    04
    
          
    
            
    
              
    
                
    human QA
    
                
    QA the spec and tests
    
                
    The user checks whether the tests really encode the spec. If the tests are wrong, fix them before implementation begins.
    
                
    pausetest contract
    
              
    
              
    
                
    
                  
    spec
    Does the HTML artifact say what I mean?
    
                  
    tests
    Do failures match the missing behavior?

    05
    
          
    
            
    
              
    
                
    /goal red
    
                
    Prove the tests fail for the right reason
    
                
    Codex runs the focused suite and confirms the failures are from missing implementation, not broken imports, bad fixtures, or setup mistakes.

    06
    
          
    
            
    
              
    
                
    /goal green
    
                
    Implement the approved spec
    
                
    Codex implements only what the spec states, uses the tests as the completion contract, and runs broader checks when shared systems are touched.

                  focused tests: passing

    09
    
          
    
            
    
              
    
                
    /simplify
    
                
    Clean up without changing behavior
    
                
    After green tests and review, simplify the implementation. The spec tests stay as the contract while complexity is reduced.
    
                
    skillpreserve behavior
    
              
    
              
    
                
    
                  
    before
    deep nesting · duplicated mapping · unclear names
    
                  
    after
    named helpers · flatter flow · same tests green

    Commit and push
